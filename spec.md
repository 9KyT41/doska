## 1. Концепт [ЧЕРНОВИК]
Редактор, где единица работы — не строка, а мысль.
Нода — контейнер содержимого (текст, аудио, изображение). Автор раскладывает
ноды на бесконечной доске и соединяет типизированными связями: последовательность
и одновременность. Собранный граф детерминированно компилируется в единый текст
без ИИ. ИИ — не автор текста, а стенографист и связыватель (с v0.2+).
Доска — это пространство. Граф — это время. Экспорт — это сборка.
Главная фраза продукта: «Сначала поймай мысль. Потом собери из неё текст.»
(Capture first. Structure later.)

## 2. Манифест / анти-требования [УТВЕРЖДЕНО]
- НЕ лист: нет постраничной ленты как основного режима.
- НЕ генератор: система не пишет текст за человека без явного заказа.
- НЕ панель инструментов: нет кнопочных панелей; функции системы живут за
  единственной кнопкой [☰] в иерархическом меню (см. D8).
- НЕ облако: v0 живёт целиком локально; проект = папка на диске.

## 3. Роли [УТВЕРЖДЕНО]
- Человек: намерение, голос, приёмка, сборка графа.
- Система (v0): записать дословно, хранить, двигать, соединять, компилировать.
- ИИ (v0.2+): связывать похожие ноды, предлагать группировки, сшивать блоки —
  только по явному запросу.

## 4. Скоуп v0 [ЧЕРНОВИК]
Двигатели, в порядке ценности и сборки:
CAPTURE (первым):
  1. Захват мысли: голос (Web Speech API), клава (N → текст → Enter),
     paste (Ctrl+V). source: ai — зарезервировано, выключено.
  2. Аудио-оригинал + стенограмма (thought.transcriptOf).
  3. Авторазмер ноды по содержимому; авторазмещение на свободное место.
  4. Автосейв.
COMPOSE (вторым):
  5. Бесконечная доска: pan/zoom; drag нод, мультивыделение.
  6. Гнёзда «до / после / вместе / доп» и рёбра seq / par / add.
  7. merge; блоки как визуальные кластеры (порядка не несут).
EXPORT:
  8. Детерминированная компиляция графа → markdown.
PROJECT (оболочка, с шага 1):
  9. Создать / открыть / сохранить проект; data.json; медиафайлы в media/.
  10. Меню [☰] — единственная точка входа в функции (D8).
Вне v0: LLM, рёбра alt, профили экспорта, синк, мультиплеер, десктоп-упаковка,
видео-части.

## 4a. UX-аксиома захвата [УТВЕРЖДЕНО]
A1: Количество действий от возникновения мысли до её существования на доске
стремится к нулю. Канонические пути:
  голос: зажал → сказал → отпустил (3 действия, 0 решений о представлении);
  клава: N → напечатал → Enter (представление выбирает система);
  paste: Ctrl+V (1 действие).
Запрещены промежуточные: создать карточку / выбрать тип / размер / подтвердить.
A2: В момент фиксации представление выбирает система: авторазмер по содержимому,
авторазмещение на свободное место. Человек управляет представлением только
в фазе compose (двигать, красить, связывать).

## 5. Критерии успеха альфы [УТВЕРЖДЕНО]
- Продиктовать 10 мыслей за 5 минут, не касаясь клавиатуры.
- Собрать цепочку из трёх нод и один ансамбль «вместе» меньше чем за минуту.
- Экспортировать читаемый черновик в markdown одним действием.
- Открыть проект с флешки на чужой машине без установки.
- Замер трения: голос ≤ 3 действия, клава ≤ 3, paste = 1; ни одного решения
  о представлении на пути.

## 6. Имя [ОТКРЫТО]
Кандидаты: «Доска»/DOSKA, «Стенограф»/STENO, «Голоспись».
Репа-заглушка: open-doska. Решение — до выкладки на GitHub.

## 7. Архитектура [ЧЕРНОВИК]
### 7.1. Принцип
Data-driven, компонентно: поведение выводится из данных (состава частей и рёбер),
а не зашивается в ядро.
### 7.2. Слои
- L1 ЯДРО: registry, node (в коде — entity), шина событий. Не знает смыслов.
- L2 КОМПОНЕНТЫ/ЧАСТИ: thought, transform, group, audio, image — каждый файл сам
  регистрируется: defaults(), serialize(), deserialize(), contextActions().
- L3 СИСТЕМЫ: capture, compose, graph, export, autosave, contextmenu, themes,
  sounds, render.
- L4 ВОРКФЛОУ: project.js — создать/открыть/сохранить, адаптер хранилища;
  js/ui/menu.js — иерархическое меню за [☰], единственная точка входа (D8).
## 7.3 — строку про ноду читать так:
node = { id, title, transform, group, parts }. title — необязательная
человеческая метка; при создании пуста и никогда не запрашивается при захвате (A1).
node = { id, transform, group, parts: [упорядоченный список] }.
Части имеют id. part thought: { id, text, source: voice|keys|paste|ai,
transcriptOf (для voice — id аудио-части), createdAt, tag }.
part audio: { id, file, duration }. part image: { id, file, caption }.
Порядок частей = порядок отрисовки внутри ноды.
### 7.4. Интроспекция
Контекстное меню собирается опросом состава ноды: кнопки приносят сами компоненты.
Шина: entity:created, component:added, entity:moved, edge:added и т.д.
### 7.5. Файловая структура
board/
  index.html
  data.json
  .gitignore
  media/               ← аудио и изображения, относительные пути
  css/core.css
  themes/              registry.js, oak.css, blueprint.css, …
  sounds/              registry.js, packs/…
  js/core/             bus.js, registry.js, entity.js
  js/project.js
  js/components/       thought.js, transform.js, group.js, audio.js, image.js
  js/systems/          capture.js, compose.js, graph.js, export.js,
                       autosave.js, contextmenu.js, themes.js, sounds.js,
                       render.js
  js/ui/               menu.js
Примечание: панель с селектором темы из шага 0.5 — временная заглушка;
в шаге 1 функция переезжает в меню [☰], заглушка удаляется.
### 7.6. Расширение
Новый тип части = новый файл в components/ + регистрация, ядро не правится.
Это формат плагинов для будущего комьюнити.

## 8. Граф, гнёзда, компиляция [ЧЕРНОВИК]
### 8.1. Гнёзда и типы рёбер
| Гнездо (UI) | Тип ребра     | Сколько                       | Смысл «много» при компиляции        |
|-------------|---------------|-------------------------------|--------------------------------------|
| «до»        | входящий seq  | сколько угодно                | нода ждёт всех предков по их порядку |
| «после»     | исходящий seq | сколько угодно, упоряд. список | список = продолжение цепочки         |
| «вместе»    | par           | сколько угодно, множество     | все связанные = ансамбль, один шаг   |
| «доп»       | add           | сколько угодно, множество     | коллекция аннотаций, поток не ломают |
«до» и «после» — концы одного seq-ребра, в данных хранится один раз.
### 8.2. Принцип cardinality
Ограничение компиляции — не счётчик дырок, а наличие правила слияния у каждого
типа. Гнёзда жадные: соединений сколько угодно, семантика «много» определена типом.
### 8.3. Алгоритм компиляции (детерминированный, без ИИ)
1. Корни = ноды без входящих seq.
2. Обход вглубь по исходящим seq в порядке edge.order.
3. par-ансамбль emit-ится одним составным шагом при первом достижении,
   участники помечаются visited; порядок внутри = порядок частей/слоёв.
4. add-рёбра собирают аннотации; в v0 — секцией в конце документа.
5. Цикл = ошибка автора: предупреждение, цикл не компилируется.
6. Markdown: нода = абзац/блок, части внутри по порядку parts;
   аудио/изображение — ссылками на media/.
### 8.4. Уровни совместности
merge = сварить в одну ноду. par = ансамбль без слияния. block = визуальный кластер.

## 10. Журнал решений [УТВЕРЖДЕНО]
- D1: В v0 нет LLM; стенографист = браузерный STT. Причина: ноль зависимостей,
  неуязвимость к пейволам и регионам.
- D2: Без сборщиков, vanilla JS, запуск двойным кликом. Причина: нулевой барьер.
- D3: Компонентная архитектура. Причина: расширяемость без переписывания ядра.
- D4: Только локально, без облака. Причина: манифест.
- D5: Нода = контейнер упорядоченных частей; источник текста = метаданные;
  merge = штатная операция. Причина: один тип контейнера вместо зоопарка карточек.
- D6: Последовательность и одновременность = типизированные рёбра; экспорт =
  детерминированный обход графа; блоки = визуальные кластеры. Причина: порядок —
  это данные графа, а не принадлежность к группе.
- D7: Гнёзда = UI над рёбрами; cardinality = семантика типа ребра, не ограничение
  дырки. Причина: автор не ограничен, компилятор не угадывает.
- D8: Системные функции — за единственной кнопкой [☰]; органы захвата
  (микрофон-пилюля, удерживаемый хоткей) — часть поверхности доски, не панели.
  Причина: аксиома A1 против D8 решается разделением «системное» и «захватное».
- D9: Кожа отделена от логики с шага 0; внешний вид только через переменные
  материалов; тема = отдельный css-файл; JS трогает лишь геометрию. Причина:
  смена скина без переписывания (проверено сменой oak → blueprint).
- D10: Режим file://: классические скрипты, глобальные неймспейсы, реестры как
  .js; без ES-модулей и fetch. Причина: выживаемость двойного клика без сервера.
- D11: Всё host-специфичное (файлы, голос, позже окно) живёт только внутри
  адаптеров/систем; остальной код не знает, где выполняется. Причина: безболезный
  переезд в десктоп (Tauri/Electron).
- D12: Capture первичен по ценности и по порядку сборки; compose вторичен.
  Причина: ценность продукта рождается до графа — в скорости ловли мысли.

## 11. Бэклог (после v0)
LLM-связыватель (v0.2); рёбра alt и ветвления; профили экспорта (сценарий/HTML);
аннотации inline; упаковка в десктоп (Tauri) и офлайн-STT (whisper-сайкар);
синк; мультиплеер; видео-части; витрина плагинов компонентов; горячие клавиши
и командная строка внутри меню.
- Онбординг: welcome-оверлей из трёх слайдов; кнопка «Папка проекта» — открыть
  папку проекта в проводнике ОС (в браузере запрещено песочницей: заменители —
  копирование пути, список файлов новой вкладкой; полная реализация — в десктопной
  версии через opener-API Tauri); новые слои подсказок по итогам юзер-тестов.
- Панель оформления, применяемая к выделенному списку нод.
- Кнопка/пункт «Папка проекта»: копирование пути (браузер, критично, рано),
  открытие в проводнике ОС (десктоп, приоритет 1).
- Мечта: трей-стенографист — софтина слушает ключевое слово автора («мысль»),
  пишет до стоп-слова («конец»); локальный whisper-сайкар, ноль звука наружу.
- Реестр субъектов (персонажи/локации/объекты): нода ссылается на субъект по id;
  группировка и поиск «всё про Машу» — по id, а не по тексту названия.
- Предложения связывания: схожесть названий (нормализация регистра/цифр/опечаток)
  и общие теги как ПРЕДЛОЖЕНИЯ автору с v0.2+; автослияние без подтверждения
  автора запрещено манифестом.

## 12. Глоссарий
Нода (entity) — контейнер частей на доске. Часть (part) — единица содержимого,
имеет id. Гнездо (socket) — UI-точка подключения ребра. Ребро seq/par/add —
связь «потом»/«вместе»/«аннотация». Ансамбль — par-группа, emit-ится одним шагом.
Блок — визуальный кластер. Компиляция — детерминированный обход графа в markdown.
Merge — слияние нод в одну. Стенограмма — текст, расшифровка аудио-оригинала
(связь thought.transcriptOf). Capture — фаза ловли мысли с нулевым трением.
Compose — фаза сборки структуры. Тема (скин) — css-файл материалов.
Звуковой пак — соответствие «событие → файл». Меню [☰] — единственная точка
входа в функции системы.
