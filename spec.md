## 1. Концепт [ЧЕРНОВИК]
Редактор, где единица работы — не строка, а мысль.
Нода — контейнер содержимого (текст, аудио, изображение). Автор раскладывает
ноды на бесконечной доске и соединяет типизированными связями: последовательность
и одновременность. Собранный граф детерминированно компилируется в единый текст
без ИИ. ИИ — не автор текста, а стенографист и связыватель (с v0.2+).
Доска — это пространство. Граф — это время. Экспорт — это сборка.

## 2. Манифест / анти-требования [УТВЕРЖДЕНО]
- НЕ лист: нет постраничной ленты как основного режима.
- НЕ генератор: система не пишет текст за человека без явного заказа.
- НЕ панель инструментов: нет кнопочных панелей эпохи печатной машинки.
- НЕ облако: v0 живёт целиком локально; проект = папка на диске.

## 3. Роли [УТВЕРЖДЕНО]
- Человек: намерение, голос, приёмка, сборка графа.
- Система (v0): записать дословно, хранить, двигать, соединять, компилировать.
- ИИ (v0.2+): связывать похожие ноды, предлагать группировки, сшивать блоки —
  только по явному запросу.

## 4. Скоуп v0 [ЧЕРНОВИК]
1. Бесконечная доска: pan/zoom.
2. Нода: упорядоченные части (thought / audio / image), время создания, тег/цвет.
3. Создание частей: голос (Web Speech API), клава, копипаста. (source: ai —
   зарезервировано, выключено.)
4. Перетаскивание нод, мультивыделение.
5. Гнёзда «до / после / вместе / доп» и типизированные рёбра seq / par / add.
6. merge: слить выделенные ноды в одну (конкатенация частей в порядке выделения).
7. Блок: визуальный кластер (рамка/цвет), порядка не несёт.
8. Автосейв в data.json + ручной Ctrl+S; медиафайлы в media/ рядом с проектом.
9. Экспорт: детерминированная компиляция графа → markdown.
Вне v0: LLM, рёбра alt, профили экспорта, синк, мультиплеер, десктоп-упаковка, видео.

## 5. Критерии успеха альфы [УТВЕРЖДЕНО]
- Продиктовать 10 мыслей за 5 минут, не касаясь клавиатуры.
- Собрать цепочку из трёх нод и один ансамбль «вместе» меньше чем за минуту.
- Экспортировать читаемый черновик в markdown одним действием.
- Открыть проект с флешки на чужой машине без установки.

## 6. Имя [ОТКРЫТО]
Кандидаты: «Доска»/DOSKA, «Стенограф»/STENO, «Голоспись».
Репа-заглушка: open-doska. Решение — до выкладки на GitHub.

## 7. Архитектура [ЧЕРНОВИК]
### 7.1. Принцип
Data-driven, компонентно: поведение выводится из данных (состава частей и рёбер),
а не зашивается в ядро.
### 7.2. Слои
- L1 ЯДРО: registry, node (в коде — entity), шина событий. Не знает смыслов.
- L2 КОМПОНЕНТЫ/ЧАСТИ: thought, transform, group, audio, image — каждый файл сам
  регистрируется: defaults(), serialize(), deserialize(), contextActions().
- L3 СИСТЕМЫ: render, drag, voice, autosave, contextmenu, graph, export.
- L4 ВОРКФЛОУ: project.js — создать/открыть/сохранить; смыслов частей не знает.
### 7.3. Нода и части
node = { id, transform, group, parts: [упорядоченный список] }.
part thought: { text, source: voice|keys|paste|ai, createdAt, tag }.
part audio: { file, duration }. part image: { file, caption }.
Порядок частей = порядок отрисовки внутри ноды.
### 7.4. Интроспекция
Контекстное меню собирается опросом состава ноды: кнопки приносят сами компоненты.
Шина: entity:created, component:added, entity:moved, edge:added и т.д.
### 7.5. Файловая структура
board/
  index.html
  data.json
  media/               ← аудио и изображения, относительные пути
  js/core/             registry.js, entity.js, bus.js
  js/project.js
  js/components/       thought.js, transform.js, group.js, audio.js, image.js
  js/systems/          render.js, drag.js, voice.js, autosave.js,
                       contextmenu.js, graph.js, export.js
### 7.6. Расширение
Новый тип части = новый файл в components/ + регистрация, ядро не правится.
Это формат плагинов для будущего комьюнити.

## 8. Граф, гнёзда, компиляция [ЧЕРНОВИК]
### 8.1. Гнёзда и типы рёбер
| Гнездо (UI)   | Тип ребра        | Сколько      | Смысл «много» при компиляции            |
|---------------|------------------|--------------|------------------------------------------|
| «до»          | входящий seq     | сколько угодно | нода ждёт всех предков по их порядку    |
| «после»       | исходящий seq    | сколько угодно, упорядоченный список | список = продолжение цепочки |
| «вместе»      | par              | сколько угодно, множество | все связанные = ансамбль, один составной шаг |
| «доп»         | add              | сколько угодно, множество | коллекция аннотаций, поток не ломают |
«до» и «после» — концы одного seq-ребра, в данных хранится один раз.
### 8.2. Принцип cardinality
Ограничение компиляции — не счётчик дырок, а наличие правила слияния у каждого
типа. Гнёзда жадные: соединений сколько угодно, семантика «много» определена типом.
### 8.3. Алгоритм компиляции (детерминированный, без ИИ)
1. Корни = ноды без входящих seq.
2. Обход вглубь по исходящим seq в порядке edge.order.
3. par-ансамбль emit-ится одним составным шагом при первом достижении,
   участники помечаются visited; порядок внутри = порядок частей/слоёв.
4. add-рёбра собирают аннотации; в v0 — секцией в конце документа.
5. Цикл = ошибка автора: предупреждение, цикл не компилируется.
6. Markdown: нода = абзац/блок, части внутри по порядку parts;
   аудио/изображение — ссылками на media/.
### 8.4. Уровни совместности
merge = сварить в одну ноду. par = ансамбль без слияния. block = визуальный кластер.

## 10. Журнал решений [УТВЕРЖДЕНО]
- D1: В v0 нет LLM; стенографист = браузерный STT. Причина: ноль зависимостей,
  неуязвимость к пейволам и регионам.
- D2: Без сборщиков, vanilla JS, запуск двойным кликом. Причина: нулевой барьер.
- D3: Компонентная архитектура. Причина: расширяемость без переписывания ядра.
- D4: Только локально, без облака. Причина: манифест.
- D5: Нода = контейнер упорядоченных частей; источник текста = метаданные;
  merge = штатная операция. Причина: один тип контейнера вместо зоопарка карточек.
- D6: Последовательность и одновременность = типизированные рёбра; экспорт =
  детерминированный обход графа; блоки = визуальные кластеры. Причина: порядок —
  это данные графа, а не принадлежность к группе.
- D7: Гнёзда = UI над рёбрами; cardinality = семантика типа ребра, не ограничение
  дырки. Причина: автор не ограничен, компилятор не угадывает.

## 11. Бэклог (после v0)
LLM-связыватель (v0.2); рёбра alt и ветвления; профили экспорта (сценарий/HTML);
аннотации inline; упаковка в десктоп (Tauri); синк; мультиплеер; видео-части;
витрина плагинов компонентов.

## 12. Глоссарий
Нода (entity) — контейнер частей на доске. Часть (part) — единица содержимого.
Гнездо (socket) — UI-точка подключения ребра. Ребро seq/par/add — связь
«потом»/«вместе»/«аннотация». Ансамбль — par-группа, emit-ится одним шагом.
Блок — визуальный кластер. Компиляция — детерминированный обход графа в markdown.
Merge — слияние нод в одну. Стенографист — роль записи дословно.
